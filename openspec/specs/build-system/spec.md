# build-system Specification

## Purpose
Сборка и dev-инфраструктура приложения: production-сборка через Vite с проверкой типов TypeScript (strict, `tsc --noEmit`), базовый путь GitHub Pages, dev-сервер с HMR, конвейер SCSS/autoprefixer, обработка статики и транспиляция под browserslist-цели.

## Requirements

### Requirement: Проверка типов при сборке
Production-сборка SHALL включать проверку типов TypeScript перед сборкой бандла: при ошибке типов сборка SHALL завершаться ошибкой без создания `dist/`. Также SHALL быть доступен отдельный скрипт `npm run typecheck` для проверки типов без сборки.

#### Scenario: Ошибка типов ломает сборку
- **WHEN** в исходниках есть ошибка типов и выполняется `npm run build`
- **THEN** сборка завершается с ошибкой компилятора типов, `dist/` не пересоздаётся

#### Scenario: Отдельная проверка типов
- **WHEN** выполняется `npm run typecheck`
- **THEN** компилятор TypeScript проверяет исходники без создания файлов вывода и завершается с кодом 0 при отсутствии ошибок

#### Scenario: Успешная сборка с типами
- **WHEN** типы корректны и выполняется `npm run build`
- **THEN** проверка типов проходит и production-сборка создаётся как прежде (пути от `/react-bot-test/`, content hash, статика из `public/`)

### Requirement: Production-сборка
Система SHALL собирать приложение командой `npm run build` в каталог `dist/` с минификацией и content hashing ассетов; результирующий каталог SHALL содержать `index.html`, ссылающийся на собранные ассеты, и изображения из каталога статики.

#### Scenario: Успешная production-сборка
- **WHEN** выполняется `npm run build`
- **THEN** в `dist/` создаются минифицированные JS и CSS с content hash в именах, `index.html` со ссылками на них и файлы `img/1.jpg`, `img/2.jpg`

#### Scenario: Повторная сборка инвалидирует кэш
- **WHEN** исходники изменились и сборка выполнена повторно
- **THEN** имена файлов с изменённым содержимым получают новый content hash, а `index.html` ссылается на актуальные имена

### Requirement: Базовый путь GitHub Pages
Production-сборка SHALL использовать базовый путь `/react-bot-test/`: все ссылки на ассеты в `dist/index.html` и URL статики SHALL корректно резолвиться при публикации сайта по адресу `https://tennalian.github.io/react-bot-test/`.

#### Scenario: Пути ассетов учитывают под-путь
- **WHEN** `dist/index.html` открыт с сервера, где сайт доступен по пути `/react-bot-test/`
- **THEN** все ассеты (JS, CSS, изображения) загружаются без 404

### Requirement: Dev-сервер с HMR
Система SHALL запускать dev-сервер командой `npm start` на порту 5000 и применять изменения исходников без полной перезагрузки страницы (HMR) с поддержкой React Fast Refresh.

#### Scenario: Запуск dev-сервера
- **WHEN** выполняется `npm start`
- **THEN** dev-сервер поднимается на `http://localhost:5000` и отдаёт работающее приложение

#### Scenario: Горячая замена модуля
- **WHEN** вносятся изменения в исходный файл во время работы dev-сервера
- **THEN** изменение применяется в браузере без полной перезагрузки страницы, состояние React-компонентов сохраняется где возможно

### Requirement: Обработка стилей
Система SHALL компилировать SCSS-файлы в CSS (dart-sass), прогонять результат через автопрефиксер по browserslist-целям и включать стили в сборку: в dev — через инъекцию стилей, в production — отдельным CSS-файлом.

#### Scenario: Компиляция SCSS
- **WHEN** бандл включает импорт `.scss`-файла
- **THEN** SCSS компилируется без ошибок dart-sass, к выводу применяются автопрефиксы согласно `.browserslistrc`

### Requirement: Обработка статики и ассетов
Система SHALL копировать содержимое каталога статики в `dist/` без изменений (изображения, шрифты), а импортируемые из кода ассеты SHALL обрабатываться конвейером Vite с content hashing.

#### Scenario: Изображения доступны на GitHub Pages
- **WHEN** сборка выполнена и `dist/` опубликован
- **THEN** файлы `img/1.jpg` и `img/2.jpg` доступны по пути `/react-bot-test/img/*.jpg`

#### Scenario: Импорт шрифта
- **WHEN** код импортирует файл шрифта (eot, woff, woff2, ttf, svg)
- **THEN** файл обрабатывается сборкой без ошибок и становится доступен в итоговой сборке

### Requirement: Транспиляция под целевые браузеры
Система SHALL транспилировать JS/JSX-исходники под browserslist-цели (`.browserslistrc`), включая JSX-синтаксис React.

#### Scenario: JSX транспилируется
- **WHEN** сборка включает JSX-компоненты
- **THEN** итоговый бандл не содержит JSX и ES-синтаксиса, не поддерживаемого целевыми браузерами

#### Scenario: Приложение работает после обновления React
- **WHEN** приложение запускается в браузере
- **THEN** чат-бот рендерится и функционирует как прежде (ответы на вопросы, очистка чата)
